deliberately limited to what has actually been supplied or approved. This file is
the checklist for closing the remaining gaps. Nothing here is a claim about the
coach; it is a list of what the app needs.

## Required photos

Four photos, each a genuine photograph of David Laid supplied by him or his
representatives with permission for use in Cadence. They must not be stock images,
images of another person, or edited to create a new expression.

| Slot | Resource name | What it must show |
| --- | --- | --- |
| Idle | `coach_david_laid_idle` | Relaxed mid-shot portrait, looking at the camera, calm expression |
| Speaking | `coach_david_laid_speaking` | Talking to camera mid-shot, mouth open, hands relaxed |
| Explaining | `coach_david_laid_explaining` | Explaining a movement, one hand raised to gesture, looking slightly off-camera |
| Encouraging | `coach_david_laid_encouraging` | Encouraging after a set, warm smile, looking at the camera |

Technical requirements:

- Portrait orientation, **4:5** aspect ratio (for example 1200 × 1500 px). The UI
  crops with `ContentScale.Crop` into a 4:5 frame, so keep the face in the upper
  third with headroom.
- Consistent framing, lens and lighting across all four, so switching between them
  does not jump.
- JPEG or WebP, sRGB, no text or logos burned in.
- File name exactly as in the table, placed in
  `app/src/main/res/drawable-nodpi/` (create the folder if it does not exist).
  Android resource names are lower-case with underscores; the app looks them up at
  runtime, so no code change is needed.
- Record the permission in `docs/coach-assets.md` or a linked approval note: who
  granted it, for which channels, and until when.

## When the photos are added

1. Copy the four files into `app/src/main/res/drawable-nodpi/`.
2. Set `approved = true` on the matching `CoachPhotoSlot` entries in
   `CoachRoster.davidLaid` (`domain/src/main/kotlin/com/cadence/fit/domain/coach/Coach.kt`)
   so the profile stops describing them as missing.
3. Run `./gradlew :domain:test :app:assembleDebug`. The slot tests assert that each
   expression has exactly one correctly named slot; update the expectations that
   assert nothing is approved yet.

Until then the profile renders a dashed, clearly labelled placeholder for each
expression and names the exact missing resource. The photo-state logic (which
expression is shown, and why) is already live and driven by real app state.

## Copy that still needs approval

Supply these as short, approved strings, then move the matching `CoachFact` entries
from `verified = false` to `verified = true`:

- **Biography**: one or two sentences.
- **Training background**: only claims the coach or his representatives will stand
  behind. Cadence does not invent credentials.
- **Programmes**: if coach-authored routines are to be published, supply the actual
  routines. They are not generated from the user's plan and presented as his.
- **Links**: one official profile or channel, if it should appear.

## How the photo state is chosen

`CoachDirector.presence` picks the expression from real app state, never randomly:

1. The user has opened a guidance topic → **explaining**.
2. A workout is in progress → **encouraging**.
3. Work finished today, or a best set in the last seven days → **encouraging**.
4. A progression suggestion or plateau warning is ready → **speaking**.
5. Otherwise → **idle**.

The line under the portrait is written by Cadence from logged sets. It is not a
quote from the coach, and the profile says so.
